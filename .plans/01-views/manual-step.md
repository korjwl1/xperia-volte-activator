# view: ManualStep (수동 개입 대기 — 모달 컴포넌트)

2026-10-05 최종 리뷰: 수동 안내는 Modal.svelte(bits-ui Dialog)를 공유해 포커스를 가두고 이전 위치로 돌려준다. Esc는 기기 변경이 진행되지 않을 때 작업을 중단한다. USB 디버깅 안내 열기는 같은 단계에서 한 번만 진행한다. SMS 내보내기 폴링은 자동 진행하지 않는다. 앱 내보내기 성공 체크 + [확인하고 진행] 후에만 백업 완결/임시 사본 정리를 요청한다. 비주얼: 기존 pane 스크롤·MD3 토큰을 유지하고 공통 모달 접근성을 적용한다.


status: implemented (mock)

2026-10-05: IMS 안내는 공통 `CommunicationPanel`을 사용한다. 발신·수신·양방향 음성, 재부팅 후·대기 후 유지 항목을 슬롯별로 기록한다. 언루팅 전 [확인하고 진행]은 대상 슬롯의 기본 통화 세 항목을 요구하지만 [통신 확인 생략하고 계속]은 항상 제공한다. 최종 IMS 확인의 통화 항목은 선택 사항이다. 관찰 폴링으로 안내를 자동 완료하지 않으며 안내를 생략한 뒤 도착한 응답도 버린다. 비주얼: 모달 내부 스크롤·공통 MD3 카드 유지.

## 목적/진입
RunProgress 실행 중 폰 측 조작이 필요한 지점(§12)에서 모달로 표시. 별도 라우트 아님.

## 지점 정의 (plan.md §12)
| id | 안내 | 자동 감지 |
|---|---|---|
| mode-wait | 부트로더(fastboot) 모드 | usb_modes에서 fastboot 인터페이스 감지 → 자동 진행 |
| flash-mode | 플래시 모드(전원 끄고 볼륨 아래 + USB) | usb_modes에서 flashmode 감지 → 자동 진행 |
| ims-check | 최종 통신 확인 | 등록 상태 표시만 갱신. 실제 발신·수신 체크는 선택 사항이며 사용자 마무리 버튼으로 진행 |
| (magisk-patch) | — | 사용하지 않음: 루팅은 자동 패치 |
| usb-debug | 폰에서 USB 디버깅 허용 | 단계 도달 시 같은 기기가 adb "device"면 안내 없이 진행, 아니면 안내 + 2초 폴링 → 연결되면 자동 진행 |
| su-grant | Magisk 루트 권한 허용 | `su -c id` 재시도 |
| magisk-patch | 폰의 Magisk 앱으로 부트 이미지 패치 | Download/magisk_patched*.img 신규 파일 감지 |
| oem-toggle | 개발자 옵션 OEM 잠금해제 켜기 | getvar 재시도 |
| mode-wait | 파란 LED(bootloader) 확인 | USB 모드 변경 감지 |
| ims-check | 최종 부팅 후 IMS 등록 확인 | dumpsys 질의(가능 시) |

## 인터랙션
- 단계별 안내 카드(번호 스텝) + [폰에서 완료했어요] 수동 ack 버튼
- 자동 감지 성공 시 모달 자동 해제. 최종 ims-check는 자동 해제하지 않고 통화 확인 여부를 선택해 마무리한다.

## 수동 단계 완료 = 실제 확인 (사용자 지시 2026-10-03)

- "폰에서 완료했어요"(건너뛰기) 대신 **[확인하고 진행]**: 누르면 그 자리에서 확인, 통과해야 진행. 실패 시 사유 표시 + 로그 [확인 실패]
  | 단계 | 확인 방법 |
  |---|---|
  | oem-toggle | 다시 읽어서 꺼진 항목 없음. "확인 불가" 항목은 통과로 보지 않음 → "폰에서 직접 켜 두었습니다" 체크 필요(안 켜져 있으면 언락 명령이 거부되어 멈춤, 폰 영향 없음) |
  | usb-debug | 같은 기기가 adb device 상태 |
  | mode-wait / flash-mode | usb_modes에 fastboot / flashmode |
  | su-grant | root_check (su -c id = uid=0) |
  | ims-precheck | 언루팅 전 통신 확인. [통신 확인 생략하고 계속]로 진행할 수 있고, 별도의 리락 검증 조건은 유지 |
  | ims-check | 대상 슬롯 IMS 등록과 실제 통화 확인을 구분. 통화 체크는 선택 사항. [통신 확인 없이 마무리]는 처음부터 사용 가능하며 SIM 없음·등록 미확인으로 파일 기록 결과를 실패 처리하지 않음 |
  | unlock-code | 형식(16자리 16진수)만 — 실제 백엔드는 fastboot가 거부하면 그 단계에서 멈추고 다시 입력받음. 목 모드(REAL_STEPS.fastboot 꺼짐)에서는 빈 입력란에 예시값 0x1234567890ABCDEF를 채운다(입력한 값은 덮어쓰지 않음) |
  | firmware(직접 지정) | firmware_dir_check: SIN 후보 하나와 같은 폴더 update.xml 지문 필수, raw IMG를 캐시에 추출. 실제 기록 전에 boot_image_check로 현재 기기 펌웨어 지문 대조 |
  | backup-notice | 동의 체크(확인 대상 아님) |
- 자동 감지(watcher)는 감지되면 자동 진행하되, 최종 ims-check는 사용자 마무리 버튼으로 진행한다.
- 목업 실행(src/lib/data/runMode.ts SIMULATED_RUN = true)에서만 "(목업) 건너뛰기" 표시 — 폰이 실제로 재부팅되지 않아 모드·루트 확인이 통과할 수 없기 때문. 실전 백엔드 연결 시 false
- 실제 백엔드의 각 단계는 명령을 보내기 전에 전제 조건을 다시 확인 (예: 리락 전 fastboot 연결·순정 부트 이미지)

- 실전 플래그가 하나라도 켜지면 목업 건너뛰기를 숨긴다. 리락은 순정 출처·현재 펌웨어·양 슬롯 완료 이력을 통과하면 부트로더 진입 안내부터 조건부 진행한다.
- root/backup/restore 엔진이 추가한 수동 안내는 재시도·재개 시 초기화하고 준비 후 다시 추가한다. 펌웨어 입력이 이미 준비됐으면 running으로 돌아가며 빈 폴더 선택은 idle로 초기화한다.

비주얼(2026-10-06): 수동 결과 확인 중 Esc가 모달을 닫거나 실행을 중단하지 않는다. 실전 백업만 활성화된 경우에도 문자·연락처 건너뛰기는 제공하지 않는다.
- 2026-10-07 (사용자 지시) su-grant:
  - 화면이 꺼져 있으면 자동으로 켠다(`screen_wake`). 잠겨 있으면 "폰 잠금을 풀어 주세요"를 표시하고 잠금 해제(`screen_state`)를 기다린 뒤 su를 요청한다.
  - Magisk는 10초 무응답이나 거부를 Shell 영구 거부로 저장한다. 그래서 거부되면 "Magisk 앱 → 슈퍼유저 탭에서 Shell 켜기"를 안내하고, 2초마다 다시 확인해 켜지면 자동으로 진행한다.
  - 상태 문구는 `wizard.suGrantHint`다.

  - 복원 엔진이 폰의 연락처 수를 먼저 본다. 이미 백업 수 이상이면(계정 동기화로 복원됨) vcf를 올리지 않고 이 단계를 열지 않는다. 실기기에서 295/295였고, 가져오면 전부 중복된다.
