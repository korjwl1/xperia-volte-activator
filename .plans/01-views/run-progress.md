2026-10-04 리뷰: 실전 복원의 failures/역할 원복 실패는 단계 실패다. SMS 준비가 loading/failed이면 확인 버튼을 잠그고 준비 실패 시 [준비 다시 시도]를 표시한다. 중단 후 늦은 이벤트·IMEI/펌웨어 응답은 generation/요청 번호로 무시하고 이벤트 등록 중 취소 시 구독을 해제한다. API 계약과 실기기 미검증 사항은 [전체 리뷰](../04-engine/code-review.md) 참조.

후속 점검: 문자 앱 원복 상태는 Rust가 기기별로 영속 저장하며, 실제 역할 확인 실패는 단계 실패다. 창 종료 시 저장 실패/창 파괴 실패를 표시하고 [작업 화면으로 돌아가기]를 제공한다. 종료를 시도하면 진행 중·수동 대기 단계는 Pending/수동 확인 0으로 돌아가므로, 복귀 후 [이어서]로 해당 단계를 다시 시작한다. 실패 단계는 실패 상태를 유지한다. 위험 단계의 종료 거부는 store에서도 검사한다. 이번 변경은 가짜 IPC 테스트만 수행했고 실제 창/폰은 테스트하지 않았다.

## 목적/진입
확정된 계획 실행. 단계 카드 + 진행률 + 실시간 로그 + 수동 개입 대기(모달) + USB 복구 UX.

## 시뮬레이션(mock) 요구사항
- fastboot 실전 분기는 백업 플래그와 무관하게 선택된 백업의 실제 완결을 강제한다. 실전 단계 재진입은 시뮬레이션 진행률을 올리지 않는다.
- 실전 언락은 잠금 상태·bootloader 모드를 명시적으로 확인한 뒤 호출하고, 결과 상태 확인 후 OS 재부팅 완료까지 기다린다. 조회/재부팅 확인 실패는 failed로 정지한다.
- 실전 리락은 Android 상태에서 현재 펌웨어/추출 이미지 대조 → 양 슬롯 복원 이력 → 부트로더 진입 → 백엔드 재검사/잠금 → 명시적인 unlocked=no → OS 재부팅 응답 확인 순서다. 모의 언루팅 완료/스킵이나 su 부재만으로 허용하지 않는다. 전체 AVB 인증을 주장하지 않는다.
- `REAL_STEPS.fastboot` 또는 root 활성 시 수동 단계의 목업 건너뛰기를 제공하지 않는다. 기본은 false이며 Rust 쓰기 feature도 기본 꺼짐.
- 실전 루팅·언루팅은 root/fastboot 모두 활성화되어야 한다. 시뮬레이션 펌웨어 업데이트와 실제 부트 기록의 조합은 시작 전에 failed 처리한다.
- 각 비동기 경계에서 실행 세대를 확인하고 늦은 구독을 해제한다. 실제 재부팅 실패는 failed로 정지하며 폴링은 질의가 멈춰도 제한 시간에 종료한다.
- 단계 순차 진행, 진행률 상승, 로그 라인append
- 루팅 단계에서 manual-wait 1회 발생
- (데모 토글) 전송 중 오류 1회 유발 → USB 복구 배너 시연

## 업데이트 확인·최종 확인 실전 (2026-10-04, `REAL_STEPS.verify`, 기본 꺼짐)
- 업데이트 확인(fw-verify): 대상 버전은 선택값(`volteConfig.firmware`, 진행 기록에 남음)에서 가져온다. 펌웨어 기록(fw-flash)에 실전 엔진이 없으면 기다리지 않고 바로 실패(지금은 항상 이 경우).

  대상 버전 펌웨어를 받아 둔 경우 그 지문과 정확히 같아야 하고, 아니면 지문에 대상 버전이 있고 업데이트 전과 기기·지역(지문 앞부분)이 같아야 통과. 지문을 못 읽으면 실패(추측 안 함)
- 최종 확인(final-verify): 엔진이 계획의 수동 안내보다 먼저 실행 — `root_reboot("os")` → 연결 끊김(60초 내) → 재연결(5분 내) → 통신 확인 안내(ims-check, 상태 표시만 자동 갱신) → 사용자 마무리 뒤 재진입하면 완료.
  "통신 확인 없이 마무리"로 끝내면 통신 체크포인트를 완료로 표시하지 않고 [미확인] 로그를 남긴다(imsUnverified). imsVerified·callVerified는 별도 기록한다. 재부팅 체크포인트가 끝났으면 재개 시 재부팅을 반복하지 않는다.

- 언루팅·리락 전 comm-check도 [통신 확인 생략하고 계속] 제공. RunStep.communicationSkipped를 기록하며 SIM 없이 언루팅이 막히지 않는다. 리락 자체의 순정 부트 체인 검증·기본 차단은 생략할 수 없다.
  OS 재부팅은 쓰기 기능 빌드(root-write/fastboot-write/efs-write)에서만 가능 — efs-write 단독은 bootloader 재부팅을 허용하지 않는다. 기본 빌드에서는 단계 실패로 사유 표시
- 실전 확인이 켜져 있으면 수동 안내의 "(목업) 건너뛰기"를 제공하지 않는다
