# 이어서 진행 (끊긴 작업 불러오기)

status: implemented

2026-10-04 리뷰: 디스크 JSON은 domain/journal의 런타임 구조 검사와 현재 모델·마스킹 시리얼 대조를 거친다. 저장·보관은 직렬 큐로 순서를 보존한다. 다른 기기에서 작업을 시작하거나 기록을 폐기하면 이전 백업 경로/완결 결과를 지운다. 백업 재개 시 기록된 Done 파일도 다시 해시 검사한다. [미검증·한계](../04-engine/code-review.md) 참조.

사용자 지시 2026-10-03: 폰이 빠지거나 앱이 꺼지는 등으로 작업이 끊길 수 있으므로 진행 상황을 기록하고,
같은 폰을 다시 연결해 [작업 시작] → 경고 페이지 [다음]을 누르면 끝나지 않은 작업을 불러올지 묻는다.

## 기록 (wizard.persist → journal_save)
- 실행 시작(launch)부터 기록. 단계 완료·수동 개입 열림/완료·오류·사용자 중단 시 즉시, 진행률·로그는 2초 간격
- 내용: 선택 옵션(SIM·펌웨어·부트로더만 작업·백업 항목·경로·마무리 옵션), 실행 계획, 단계별 상태와 로그, 받은 펌웨어 경로
- 멈춘 사유: USB 오류·사용자 중단은 명시 기록. 기록이 없으면 마지막 상태로 추정
  (진행 중 → "앱 종료 또는 연결 끊김", 수동 대기 중 → "폰 확인 대기 중 종료 또는 연결 끊김")
- 모두 끝나면 done으로 보관 → 다시 묻지 않음
- 언락 코드·IMEI는 기록하지 않음

## 불러오기 창 (components/ResumeJournal.svelte)
- 제목 "이전에 하던 작업이 있습니다! 불러올까요?" + 기기·마지막 기록 시각
- 멈춘 지점(단계·사유·마지막 로그 4줄) → 진행 상황(완료/여기서 다시 시작/대기) → 선택했던 옵션
- [새로 시작]: 기록을 discarded로 보관하고 1단계로 / [이어서 진행]: 옵션·진행 상황 복원 후 실행 화면(자동 시작 안 함)
- 창 내용이 길면 창 안에서만 스크롤

## 세부 작업 체크포인트
- 단계마다 세부 작업 목록(RunStep.sub): 백업·복구는 선택 항목별, 루팅은 Magisk 받기 → 전송 → 패치 → 확인 → 기록 → 앱 설치,
  VoLTE 적용은 슬롯별 등. 세부 작업이 끝날 때마다 [체크포인트] 로그 + 즉시 저장

## 프로그램 종료
- 실행이 끝나지 않은 상태에서 창을 닫으면 확인 창: [작업 화면으로 돌아가기] / [종료]
  - 되돌리기 어려운 단계(risk danger)가 진행 중이면 닫을 수 없음 — [종료] 없이 "이 단계가 끝나면 닫을 수 있습니다" + 경고
- 작업 중 PC 보호(guard.rs): 절전 방지, Windows 종료·재시작·로그아웃 보류(사유 표시). 사용자가 그래도 종료하면 사유 기록
- 프로세스 강제 종료(작업 관리자 "프로세스 끝내기")는 막지 않음 — 진행 기록으로 대응
  - [종료]: 멈춘 사유("작업 중에 프로그램을 종료" / "폰 확인을 기다리는 중에 프로그램을 종료")를 남기고 기록 저장을 마친 뒤 창 닫기
  - 사용자가 이미 [중단]한 경우 그 사유를 유지
- 강제 종료·정전 등 확인 창 없이 꺼진 경우: 마지막 저장(최대 2초 전) 기준으로 상태에서 사유 추정
- 권한: core:window:allow-destroy (확인 후 창 닫기)

## 이어서 진행 규칙
- 완료된 단계는 건너뛰고, 멈춘 단계는 끝낸 세부 작업 다음부터
- 각 단계·세부 작업은 시작할 때 기기 상태로 실제 완료 여부를 확인 (기록과 기기 상태가 다르면 기기 상태 기준)
- 언락이 아직이면 사전 준비를 다시 진행(언락 코드 재입력)
- 디버깅: 실전 코드 작업 시 journal/*.json(진행 중) · *.done.json · *.discarded.json에서 단계별 로그·체크포인트 확인

- 최종 VoLTE 확인 생략(imsUnverified)도 기록·복원
- 실행 세대(runGen): 중단·처음으로·새 실행·재개 시 증가 — 그 전에 시작된 비동기 작업(펌웨어 받기, 자동 감지, 확인)은 결과를 버림
- 창 닫기 시 기록 저장에 실패하면 알리고, [종료]를 한 번 더 눌러야 기록 없이 닫힘
- 종료를 시도한 뒤 저장/창 종료 실패로 화면에 돌아오면 실행은 정지 상태이며, 진행 중·수동 대기 단계는 Pending/수동 확인 0으로 초기화된다. [이어서]로 다시 시작한다. 실패 단계는 [이 단계 다시 시도]를 사용한다. 늦은 비동기 응답은 무시하며 창 종료 예외도 표시한다.
- 진행 기록의 저장/읽기 모두 8MiB 상한. 문자 앱 원복은 별도 기기별 영속 기록으로 보존한다([전체 리뷰](../04-engine/code-review.md)). 실제 창 종료·강제 종료·정전·폰 재연결 실험은 하지 않았다.

- 작업 시작 때의 SIM 구성(슬롯·통신사·상태)을 기록. 이어서 진행할 때 달라졌으면 불러오기 창에 경고하고, 완료된 통신 확인·최종 확인도 다시 진행
