## 추가 보강과 범위 판단

- 리락 이력의 기기·순정 바이트·양 슬롯 조건을 유지하고, OS 조회에서 **관찰한 현재 펌웨어**가 이미지의 출처 지문과 다르면 거부한다. 패치 이미지는 순정 부모 해시를 기록하고 순정 리락 입력으로 쓰지 않는다. 단순 경과 시간은 슬롯 내용 변경의 증거가 아니므로 임의 만료시간을 추가하지 않았다. 외부 도구의 수정이나 OS에서 관찰하지 못한 펌웨어 변경까지 완전 검증하는 기능은 아니다.
- 손상 플래시 이력은 명시적으로 원본 보관 후 분리할 수 있다. 정상 이력은 이 명령으로 지우지 않는다. UI는 순정 양 슬롯 복원 단계로 돌아가며 잠금 명령을 자동 실행하지 않는다. 이력을 보관했다는 사실은 이전 플래시 성공의 증명이 아니다.
- 기본 배포의 frontend live 플래그/Cargo write 기능 꺼짐, 실제 API의 비활성 명령 거부, EFS-only OS 재부팅을 테스트한다. Rust 프로세스 잠금 테스트는 PID별 경로를 사용해 실행 중인 앱의 전역 잠금 파일과 충돌하지 않는다. 운영 잠금의 범위는 유지한다.
- 모든 모달을 bits-ui Dialog 공통 컴포넌트로 묶어 이름·포커스 제한/복원·Esc 동작을 제공한다. 실제 쓰기 도중 Esc로 중단되지 않도록 기존 위험/작업 중 조건을 유지한다. 실전 실행 화면에서는 시뮬레이션 스위치를 숨긴다.
- 의존성 audit에서 SvelteKit의 `cookie 0.6.0`에 낮은 위험도의 [GHSA-pxg6-pf52-xh8x](https://github.com/advisories/GHSA-pxg6-pf52-xh8x)를 추가 확인했다. 같은 parse/serialize API의 수정 버전 0.7.2로 한정해 override하고 lockfile을 갱신했다. 설정 위치는 [pnpm 공식 설정](https://pnpm.io/settings)을 따른다.
- 현재 설계 문서/AGENTS의 mock 폴백·무조건 리락 차단·CLI 해시 오기를 정리했다. 과거 리뷰 문서는 후속 정책 안내와 함께 당시 판단을 보존한다.
- 긴 wizard/restore 파일 자체는 동작 오류가 아니다. 이번에는 SMS ZIP 검사, 원자 파일 발행, 실행 정책/모달을 공통 함수·모듈로 분리했다. 실기기 검증 직전 대규모 상태 머신 재작성은 추가하지 않았다. ZIP 코드도 목적이 서로 다른 펌웨어 Range 파서와 문자 전체 파일 검사까지 하나로 합치지 않았다.
- EFS의 프레이밍·제한/타임아웃·불명 결과 재전송 금지·출처 프리셋·스냅샷/롤백 입력·리드백을 확인했다. 이번에 추가로 확정한 내부 결함은 없다. SIM·통신사는 사용자 선택을 유지하고 SIM 감지로 작업을 바꾸지 않는다. 10 시리즈 전용 예외/근거 없는 모델 제한은 추가하지 않았다.

새 테스트만 수정 코드에 통과시키는 데 그치지 않았다. `c42a326`의 관련 함수만 임시로 복구해 동일 테스트를 실행하고, 반드시 수정된 함수로 되돌렸다.

- 기존 APK 파서: 서명 크기 16에서 실제 slice 패닉 재현, 두 번째 다른 서명자의 인증서 누락 재현.
- 기존 CLI 세션 저장: 정상 세션 뒤 빈 ADB 조회가 키 목록을 지우는 실패 재현.
- 기존 백업 재개: 재수신 중단을 반복하면 이전 성공 사본의 해시/성공 기록을 잃는 실패 재현.
- 수정 후: 잘린 APK/변조 길이·잘린 ZIP/JSON·MMS CRC 손상·타 기기 백업·검증되지 않은 이미지·변경 펌웨어·손상 이력·복사 실패·중복 안내·기록 I/O 실패를 포함해 회귀 테스트 통과.

기본 빌드 차이는 쓰기 기능이 꺼졌을 때만 포함되는 게이트 테스트와 dev-cli 전용 테스트 때문이다. 자동 매트릭스의 기존 8개 ignored 중 실제 APK 핀과 원본 프리셋 검사는 장치 접근 없는 opt-in으로 따로 실행했다. 나머지 실기기·네트워크·PC 수동 검사는 실행하지 않았다. MSVC 링크가 생성 라이브러리 경로를 stdout으로 출력해 일반 build가 `linker_messages` 경고를 표시하지만 clippy 소스 경고 검사는 통과했다.

개발용 debug CLI도 `target/dev-cli/xva-dev-readonly.exe`(dev-cli)와 `xva-dev.exe`(dev-cli + 모든 쓰기 기능)에 새로 복사했다. 오래된 빌드 실행을 피하려면 [dev-cli 사용법](dev-cli.md)의 cargo run/build를 사용한다.

내보내기 형식과 실패 후에도 닫힐 수 있는 ZIP 구조는 [sms-ie 메시지 코드](https://github.com/tmo1/sms-ie/blob/master/app/src/main/java/com/github/tmo1/sms_ie/ImportExportMessages.kt), [Worker의 실패 처리](https://github.com/tmo1/sms-ie/blob/master/app/src/main/java/com/github/tmo1/sms_ie/ImportExportWorker.kt)를 확인했다. APK 컨테이너 구조는 [AOSP v2 서명 명세](https://source.android.com/docs/security/features/apksigning/v2)와 대조했다.

오프라인 검증 결과로 실기기 동작을 보장하지 않는다. XQ-DQ44의 실제 드라이버/모드 전환, sms-ie 사용자 조작/초기화 후 복원, 양 슬롯 기록·리락 후 부팅, DIAG/EFS, IMS·사용자 발신/수신/음성은 [단일 실기기 체크리스트](device-test-checklist.md)에 남겼다. 기본 배포에서는 모든 쓰기 기능을 계속 끈다.
