# 작업 종류·모듈 세트 GUI 검토 — 2026-10-08

상태: main GUI/계획 수정·기존 루트 도구 통합·오프라인 검증. 전체 Newflasher 업데이트와 새 기능 실기기 검증은 미완료.

## 지시와 구현의 차이

초기 작업 종류 문서는 계획으로만 남았고 루트 도구가 첫 기기 화면의 별도 버튼으로 구현돼 있었다. 원래 요청한 시작 직후 3열 분기와 수동 그리드를 실제 코드에서 대조하지 못했다. 모듈도 문서의 A/B 세트 대신 개별 항목으로 표시돼 의존 세트와 자동 루팅 유지 옵션이 빠졌다.

main의 기존 GUI 수정과 merge-check의 기존 루트/네이티브 코어 구현을 함께 통합했다. 다른 워크트리의 미커밋 기기 검증 기록과 vendor의 로컬 생성물은 포함하지 않는다.

## 후속 코드 검토

설정 안내 후 OS 재부팅은 이전 모듈의 pending 상태만으로 새 부팅을 증명할 수 없었다. 재부팅 직전 native inventory의 bootId를 다시 조회하고 다음 설치 전에 다른 bootId를 요구한다. 설치 후 및 폰 설정 후 모두 적용하며 모듈 활성·엔진·불확정 상태도 함께 검사한다. 재부팅 ACK만 성공한 경우 후속 설치를 거부하는 테스트와 native 직렬화 검사를 추가했다.

모듈 설치 기능이 없는 빌드는 자동 계획의 첫 기기 작업 전에 PC capabilities 검사로 중단한다. 모의 러너가 모듈 설치 성공을 표시하지 못한다. 진행 기록은 세트·동의·의존성과 실제 root-modules 단계의 일치를 검사한다.

- 프론트/domain/facade 테스트: 169 passed. 의존 세트, 설치 순서, 부팅 ID 변경, 취소·실패, 영수증 재개, 기록 검증과 실행 게이트를 포함한다.
